# AGENTS.md

Route card for the `surface-catalog` stats source family.

## Ownership

This family owns catalog entry shape, surface-profile vocabulary, and the
authority ceiling attached to each committed derived summary surface. It does
not own owner-local facts, receipts, verdicts, route state, memory, or runtime
truth. A catalog entry is a bounded description and discovery route, not proof
that its source is complete or current.

## Conditional source routes

When catalog meaning or access is selected, follow the authored profiles,
surface-profile schema, catalog schema, source-home manifest, and the named
consumer-regrounding or recurrence route. Open `SURFACE_STRENGTH_MODEL.md`,
`CONSUMER_REGROUNDING.md`, or the MCP contract only when that question needs
their human or access explanation.

The `Mechanics crosswalk` is the recurrence component-manifests part, the
Boundary Bridge consumer-regrounding part, and the Release Support artifact-
bundle part. None may strengthen catalog authority.

## Change law

- Every entry keeps source ref, schema ref, input posture, owner-truth inputs,
  authority ceiling, consumer risk, and live-state posture.
- The strength model owns the closed vocabulary used by profiles. Change it
  with profile and catalog proof; do not retain unused classes or current
  surface state in this card.
- Generated catalog changes come from authored profiles and the deterministic
  builder. Do not edit output or restore an in-code specification table.
- Keep `docs/ARCHITECTURE.md` as the stable public derived-view contract; exact
  lifecycle state stays in authored profiles, generated catalog, and decisions.
- Keep public access read-only and derived-only; transport and runtime changes
  return to the stack owner.
- High-risk or thin-input surfaces route consumers back to stronger owner
  evidence.

## Conditional validation and closeout

Use root `VALIDATION.md` for generated catalog and route checks, then the
nearest catalog-owning mechanic validation. Report authored inputs, builder,
output parity, access posture, owner evidence, and what a catalog check cannot
prove.
