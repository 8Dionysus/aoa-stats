# AGENTS.md

Route card for `stats/operation-contracts/`.

## Role

This family owns one schema-backed source record for each active part-local
stats operation that does not publish a public catalog read model. Part-local
stats operations are represented by one record each. Each record owns the
bounded question, input maturity, authority ceiling, consumer risk,
forbidden inference boundary, and return to stronger owners. Payload, scripts,
examples, tests, and lifecycle remain with the named mechanic part.

## Conditional route

When an operation is selected, follow `operation-contract.schema.json`, its
active record, the exact mechanic contract, the named validation card, and the
reciprocal topology entry. Open the family README only when its human contract
explanation is needed.

## Law

- Every routed mechanic part has exactly one active record and a reciprocal
  topology link. Derive inventory from authored records and crosswalks; do not
  freeze current counts.
- Keep `payload_class`, `mechanic_contract_ref`, and `validation_ref` equal to
  the topology part.
- Give every `owner_truth_inputs.owner_repo` an exact owner-return route,
  including a bounded return beneath the canonical mechanic owner.
- State whether stronger-owner inputs are bound, declared by reference, or
  symbolic. A bound input requires mechanic-local proof and explicit source-home
  registration; planned input is not current evidence.
- Do not add a public surface profile merely to make a part visible here.
- Do not copy mechanic schemas, examples, scripts, tests, metric lists, or
  generated output under `stats/`.
- Part-local registries and prose remain weaker than stronger-owner evidence.

## Conditional validation and closeout

Use root `VALIDATION.md` for source-home/topology selection, then the exact
part-local validation route. Report the bounded question, input posture,
consumer risk, owner-return chain, proof limits, and whether any generated
surface changed.
